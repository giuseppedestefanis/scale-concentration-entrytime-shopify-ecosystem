# Replication package

Replication package for:

> Fabrizio Assabese, Peter-Jan Celis, and Giuseppe Destefanis.
> *Scale, Concentration, and Entry Timing in the Shopify App Ecosystem:
> A Longitudinal Study of Platform Governance and Application Survival.*

Extended version of:

> Assabese, F. and Destefanis, G. *Scale, Concentration, and Entry Timing in the Shopify App Ecosystem.* IWSiB '26. DOI 10.1145/3786158.3788552.

## What this repository contains

The scripts behind every calculation in the paper, in two layers:

1. **`scripts/`** — the analysis pipeline. Ten numbered scripts that take the
   raw inputs and produce every result, table and figure in the paper:
   input validation, panel construction and linkage, the replication bridge
   to the base paper, descriptives and concentration, the four governance
   event studies, the rolling entry-timing grids, survival analysis
   (Kaplan-Meier and Cox), exit redistribution, robustness checks, and the
   early-warning model. `make all` runs them in order and writes the outputs
   to `results/`, `tables/` and `figures/` locally.
2. **`archival/`** — the historical reconstruction pipeline. The scripts that
   rebuilt 2012-2026 App Store listing histories from the Internet Archive's
   Wayback Machine (discovery, acquisition, extraction, validation), the
   panel-assembly scripts, the run logs, and the extracted data itself
   (pricing, categories, listing metadata), which is redistributable because
   it derives from public archive content.

Generated outputs are not committed; the paper is the record of the results,
and `make all` regenerates all of them.

## What it does not contain

Store Leads data. Its commercial licence does not permit redistribution, so
the September 2025 snapshot exports, the weekly installation counts, the
weekly review counts, and every file derived from them are excluded.
`data/README.md` documents the exact extracts required. A reader who obtains
the same extracts can reproduce every result: `scripts/00_validate_inputs.py`
checks an extract before anything runs, and `archival/README.md` documents
the verified path that reassembles the application-week panel from the
archival data plus the Store Leads files.

## Layout

```
replication_package/
├── README.md            this file
├── CONVENTIONS.md       rules every script must follow
├── requirements.txt     pinned Python dependencies
├── Makefile             `make all` reproduces everything in order
├── scripts/             numbered pipeline scripts (the only source of results)
├── archival/            Wayback Machine reconstruction pipeline + its data
├── data/
│   ├── README.md        raw-input documentation and availability
│   └── derived/         intermediate datasets, regenerated by `make all`
├── figures/             output directory (regenerated, not committed)
├── tables/              output directory (regenerated, not committed)
└── results/             output directory (regenerated, not committed)
```

## Setup and run

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
make all          # runs every script in numeric order
make validate     # step 00 only: check input data is present and as expected
```

Raw input data is expected outside this package (see `data/README.md`):
- `../raw_data/dataset_Extended/weekly_dataset.csv` (weekly panel)
- `../raw_data/Shopify data september 2025/` (September 2025 snapshot exports)

Override locations with environment variables `PANEL_CSV`, `SNAPSHOT_DIR`.
